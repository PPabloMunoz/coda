# AGENTS.md

Coda: self-hosted music library manager (Go + SQLite) — a simpler, faster Lidarr for files only. Scope: read audio files from configured roots, write tags, and link local files to releases via tags so libraries work with Navidrome. Non-goals: downloads, download-client integration, automation. Early prototype — expect breaking changes.

## Git workflow

- `main` is protected — never commit or push to it directly. Do all work in topic branches and merge via PRs.
- Create branches and PRs with the `gh` CLI (`gh pr create`, `gh pr status`, `gh pr view`). Keep PRs small and focused.
- Agents never merge PRs — only create them and inspect them (`gh pr view`, `gh pr status`). Merging is done by the human.
- After creating a PR, offer to clean up local git: `git switch main`, `git pull`, `git fetch origin --prune`, and delete the local topic branch the PR was created from.
- Commit messages (when used) and PR titles follow Conventional Commits: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`, `perf:`, `ci:`, `revert:` (e.g. `feat: add discography import status`).

## Commands

Use `just` (wrappers around `go`):

- `just run` — `build`, then `./bin/coda` (use `just check` before finishing). The UI is committed static files under `web/static/` (no build step).
- `just check` — full gate: Go `fmt-check` + `go vet` + `golangci-lint` + `go test` + `go build ./...`. Run after every change, before finishing.
- `just fmt` — apply formatting: Go (`golangci-lint fmt`). Run it when `just check` reports format diffs, then re-run `just check`.
- `just build` / `just build-prod` — `go build -o bin/coda ./cmd/coda` (`build-prod` adds `CGO_ENABLED=0` static, pure-Go SQLite, no cgo needed).
- `just tidy` — `go mod tidy && go mod vendor` (`vendor/` is gitignored local output, not committed).
- `just db-reset` — macOS-only (`rm -f "$HOME/Library/Application Support/Coda/"*.db*`); on Linux remove `$XDG_DATA_HOME/coda/*.db*` (or `~/.local/share/coda/`) or the `CODA_DB_PATH` target instead.

Env overrides: `CODA_CONFIG=/path/to/config.yaml`, `CODA_DB_PATH=/path/to/coda.db`, `GIN_MODE=debug` (opt back into Gin's debug route dump; release is the default). Tests exist for `internal/errors` and `internal/utils` (`go test ./...`) — don't add test scaffolding unless asked.

## Runtime

- Entrypoint `cmd/coda/main.go`: `GetConfig` → `GetDBPath` → `NewStore` (runs goose migrations) → `AddRootDirs` (fatal on error) → `musicbrainz.New` (single shared client) → `NewQueue`/`NewRunner`/`NewScheduler` → `NewHandler` (returns `*gin.Engine`; Gin runs in release mode unless `GIN_MODE` is set) → `http.Server{Handler: router.Handler()}` in goroutine (`ReadHeaderTimeout` 5s) → `runner.Start` + `scheduler.Start` + `EnqueueScan` → 10s graceful shutdown. Scan ctx is 10 min, discography import ctx is 30 min; scan failure only logs and keeps serving stale DB.
- The scan itself never modifies audio files; tag writes happen only via `POST /api/v1/files/{id}/link` and `DELETE /api/v1/files/{id}/link` (`{id}` is the old ServeMux spelling — Gin routes use `:id`; never mix them).
- First start creates `config.yaml` with defaults (`port: 8687`, empty `roots`); edit `roots` to absolute existing dirs. Validation trims/cleans, rejects empty/relative/duplicate/nested roots, resolves symlinks, and `Stat`s each root is a dir.
- State location is per-OS: macOS config + DB both under `~/Library/Application Support/Coda/`; Linux config is `~/.config/coda/config.yaml` but DB is `~/.local/share/coda/coda.db` (or `$XDG_DATA_HOME/coda/`); Windows prefers `LOCALAPPDATA`/`AppData`. `bin/`, `*.db*`, and `/testdata/` are gitignored (testdata holds local real MP3s only).

## Layout (`internal/`)

- `config/` — `config.yaml` + DB path resolution (per-OS defaults, `CODA_*` overrides). DB filename constant embeds SQLite pragmas (`WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout`); `CODA_DB_PATH` is passed through with pragmas appended.
- `store/` — SQLite via `modernc.org/sqlite`, migrations embedded (`migrations/*.sql` via goose). `db.SetMaxOpenConns(1)` is required — don't raise it. New schema changes go in `0002_*.sql`; never edit `0001_init.sql`. All errors are `internal/errors`: `Wrap` at each `st.db` origin site, pass through helper errors untouched.
- `errors/` — the only error vocabulary. `AppError{Code, Message, Cause}`: `Error()` returns only the safe `Message` (never `Cause`), `Unwrap()` exposes `Cause`, `Is()` matches by `Code` so `Wrap` preserves identity for `errors.Is`. Sentinels: `ErrNotFound` (`NOT_FOUND`), `ErrUnauthorized`, `ErrForbidden`, `ErrAlreadyExists`, `ErrInvalidID` (`INVALID_ID`), `ErrInvalidInput`, `ErrMusicBrainzFailed`, `ErrInternal`. `Wrap(sentinel, cause)` allocates a new instance (sentinels are never mutated); `Is`/`As` delegate to stdlib; `Get(err)` returns the first `*AppError` in the chain. Rules, load-bearing: wrap at the origin site (where the raw error is born) with the code matching its meaning + `fmt.Errorf("op: %w")` context inside; pass already-classified errors through untouched (plain `fmt.Errorf("…: %w")` context is safe, it preserves `Code` — re-wrapping with a different sentinel overwrites it and is a bug). Signatures stay `error`, never `*AppError` (typed-nil trap). Stdlib only — no Gin, no `net/http`, no status codes; the Code→status table lives in `server/errors.go`. Codes are the API contract: never rename one.
- `library/` — filesystem walk: skips symlinks, non-regular files, unreadable entries, and non-audio extensions (`SupportedFormats` map). Never follow symlinks.
- `tags/` (`go.senan.xyz/taglib`, `bogem/id3v2` for MP3 TXXX normalize) — `Snapshot`/`Read` is the read view; `WriteTags`/`ClearTags` implement link/unlink and touch only `LinkKeys` (title/album/artist(s)/album-artist(s)/track/disc/date/MBIDs/release-type/status). `ARTISTS` comes only from the `ARTISTS` frame, never by splitting `ARTIST`; `ArtistRaw` is display-only. Bad `TRACKNUMBER`/`DISCNUMBER` parses to 0 (missing), never an error.
- `musicbrainz/` — client enforces ~1 req/1.1s rate limit, 3 retries with backoff (`Retry-After` aware), mandatory `User-Agent`. Lowercase-hex MBID validation; `apperrors.ErrNotFound` maps to 404, `ErrInvalidID` to 400, `ErrMusicBrainzFailed` to 502 via `server/errors.go`.
- `server/` — Gin (`gin.New()` + global `Recovery`; no access logging — the API stays silent like the UI serving. `NewHandler` returns `*gin.Engine`, routes in a `/api/v1` group, `:id` params — never ServeMux `{id}` spelling). Routes: `GET /api/v1/health`, `GET /api/v1/stats`, `POST /api/v1/scan`, `GET /api/v1/files` (+ `stats`, `/:id`, `/:id/suggestions`, `POST /:id/link`, `DELETE /:id/link`, `POST /:id/refresh`), `GET /api/v1/artists` (+ `/:id`, `/:id/import`, `POST /`, `POST /:id/refresh`, `DELETE /:id`, `/:id/cover`, `POST /:id/cover/refresh`), `GET /api/v1/musicbrainz/artists`, `GET /api/v1/release-groups` (+ `/:id`, `/:id/cover`, `PUT /:id/update`, `DELETE /:id`), `GET /api/v1/releases` (`?group=`, `/:id`, `/:id/cover`, `POST /:id/cover/refresh`), plus embedded UI (see `web/`). All failures go through `(h *Handler) writeAppError` (`server/errors.go`): `apperrors.Get` → Code→status table (`NOT_FOUND`→404, `UNAUTHORIZED`→401, `FORBIDDEN`→403, `ALREADY_EXISTS`→409, `INVALID_INPUT`/`INVALID_ID`→400, `MUSICBRAINZ_FAILED`→502, default→500) → `AbortWithStatusJSON` with `{"error","code"}` (client-safe message only; cause goes to the log line with method+route). Unknown `err` → 500 `An unexpected error occurred`. Missing entity is 404 with that object (the web client treats 404 as `null`) — never `store.ErrNotFound` (deleted) and never a bare `fmt.Errorf` outermost (degrades to 500). `POST /api/v1/artists` returns `304` (`null` body) if the MBID is already stored (and requeues a refresh), else fetches MusicBrainz, `CreateArtist`, enqueues discography import, and returns `201`. List endpoints paginate (`limit` 1–100 default 20, `offset` ≥ 0); `GET /api/v1/musicbrainz/artists` uses `limit` 1–25 default 10 and requires `q` ≥ 2 chars. Enqueue/refresh state lives in `tasks.Queue` (`artistImports` map + mutex), not a handler-local goroutine. Helpers take `*gin.Context` (`parseLimitAndOffset`, `requireMBID` → `ErrInvalidID`, `requireLocalFileID` → `ErrInvalidID`).
- `tasks/` — serial FIFO `Queue` (`run` loop) + `Runner` dispatch (`scan-roots`, `import-discography`) + `Scheduler` for periodic work. Dedup only for artist imports while `queued`/`running`; scans have no dedup (`TODO` in `queue.go`). Scan upserts by absolute path (preserving `track_id`) and prunes rows with `scanned_at` older than the run. Import status is `idle/queued/running/done/failed` (`GET /api/v1/artists/{id}/import`, `POST /api/v1/artists/{id}/refresh` → `202`). Runner uses `apperrors.Is(err, apperrors.ErrNotFound)` to skip imports for removed artists.
- `utils/` — tiny stderr `Logger` (`Info`/`Error` + `f` variants, no levels to configure) plus `ValidateMBID` and `NullIfEmpty`.
- `web/` — vanilla static UI (`web/static/`, no build step; all calls use `/api/v1/*`). Committed HTML/CSS/JS embedded by `web/embed.go` (`go:embed all:static`) and served by `server/web.go` after the `/api/v1/*` routes: exact `GET /` + `HEAD /`, `pageRoutes` map for UI pages (trailing slash tolerated), real files (`/css/*`, `/js/*`, `/logo.png`, …), `NoRoute` for the rest (`/api/*` → JSON 404, else root `index.html` fallback; 404 `web build missing` fallback when `static` is absent). Never use Gin's `c.FileFromFS` with `index.html` — it delegates to `http.FileServer`, which 301-redirects `*/index.html` to `./` (self-redirect loop on `/`); `serveFSFile` reads bytes from the embed FS and writes them via `c.Data` instead. Don't expand UI scope or add frontend infra without asking.

## Schema / metadata rules (load-bearing)

- Entity split is deliberate: `artists / artist_credits / release_groups / releases / tracks / local_files` (one release per release-group; recording MBIDs live on `tracks`). Credits reference `artist_credits(id)` only — never add an `artist_id` shortcut or collapse to one artist string.
- The core job is linking files to music: `local_files.track_id` ties a scanned file to a release track, and tags written back to files must stay Navidrome-compatible (standard frames only — don't invent custom tag fields).
- MusicBrainz IDs are `TEXT UNIQUE` (nullable until matched); refresh by MBID, never text matching. MBID columns enforce 36-char length.
- Don't add services (Redis, queues, K8s), download clients, automation, `docs/decisions|`architecture|roadmap` files, or unrelated refactors. Keep changes small; single binary + SQLite only.
